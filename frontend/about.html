How Redeemo Works

The idea, the mechanics, and what's actually running under the hood.

The Idea

Redeemo simulates a gamified rewards program, the kind you'd see in a mobile app: complete small tasks ("quests") to earn tickets, then trade those tickets in for gift cards, in-game currency, streaming subscriptions, or charity donations.

It's built as a portfolio project, not a real rewards program — no quest here pays out actual money or products. The point is to demonstrate the full mechanics of a system like this, done properly.

What's Different From a Typical Demo

A lot of demo "rewards" apps keep the ticket balance in the browser's localStorage, which means anyone can open devtools and hand themselves unlimited tickets. Redeemo doesn't do that.

Every balance change happens on the server: completing a quest, checking whether its cooldown has passed, and deducting tickets on redemption are all verified against a real database, not trusted from the browser. The frontend only ever displays numbers it fetched from the API — it never invents or edits them locally.

How a Quest Actually Works

Each quest has a fixed reward and a cooldown window (some reset every few hours, some once a week, one — rating the app — only once ever). When you click "Complete":

  1. The server looks up when you last completed that specific quest.
  2. If the cooldown hasn't passed yet, it rejects the request (HTTP 429) and tells the frontend exactly when it'll be available again.
  3. If it's allowed, your ticket balance is increased and the completion is logged with a timestamp — that log is what the next cooldown check reads.

What's Under the Hood

Backend: Node.js + Express, with a SQLite database. Passwords are hashed with bcrypt before they're ever stored; sessions are handled with signed JWTs sent in the Authorization header on every request.

Frontend: plain HTML, CSS, and JavaScript — no framework or build step. Every page fetches its data from the API on load rather than hardcoding it, so quests and rewards can be added or changed on the server without touching the frontend at all.

FAQ

Is this a real rewards program?

No — it's a portfolio project. No quest pays out real money, gift cards, or donations.

Can I add my own quests or rewards?

Yes, if you're running this yourself — they're seeded in the backend's database file and can be edited or added to directly.

Why tickets instead of points or coins?

Mostly a design choice — it let the whole visual identity lean into a physical, tear-off ticket-stub look instead of a generic points dashboard.
